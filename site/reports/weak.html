Summary

The submission proposes GlobalGate, which multiplies each attention head by a learned, input-independent scalar passed through a sigmoid (Section 2, Eq. 1: head'_h = σ(g_h)·head_h). It claims this 'solves long-context reasoning', outperforms 'all existing methods on every benchmark', and is 'universal' across architectures, tasks and modalities (Abstract, Sections 1 and 4). The only empirical evidence is Table 1: on LongQA-Mini, a 200-question author-written dataset at a 2k-token context, GlobalGate (5 epochs) reaches 74.0% and a vanilla 125M Transformer (1 epoch) reaches 61.0%.

Assessment

All three reviewers rated the paper 1 with confidence 5. Their objections are concrete and each one can be checked against the text, so this is not harshness carrying the decision. I checked each point against the submission, and every one holds:

  1. The comparison is confounded (fatal). Section 3.1 trains the baseline for 1 epoch and GlobalGate for 5. The 13-point gap in Table 1 (74.0 vs 61.0) therefore cannot be attributed to Eq. 1. There is no equal-budget or converged baseline. All three reviewers raised this.
  2. Hyperparameters were tuned on the test set (fatal). Section 3.1 says 'we use the same 200 questions to select hyperparameters and to report results.' No held-out estimate exists. All three reviewers raised this.

Revision plan

  1. must Confounded comparison: the baseline is trained for 1 epoch and GlobalGate for 5 (Section 3.1), so the Table 1 gap (74.0 vs 61.0) cannot be attributed to Eq. 1.
    → Retrain the vanilla Transformer with an identical epoch count, schedule and tuning budget, and also train both models to convergence. Report both comparisons. R1, R2, R3
  2. must The same 200 LongQA-Mini questions are used for hyperparameter selection and for reporting (Section 3.1).
    → Create separate dev and test splits, tune only on dev, and report test results. Add results on established public long-context benchmarks (e.g., RULER, LongBench, needle-in-a-haystack). R1, R2, R3
  3. must Claims of solving long-context reasoning, universality across architectures, tasks and modalities, and beating 'all existing methods' (Abstract, Sections 1 and 4) are unsupported. Only 2k context is tested, and Section…
    → Scope claims to what is tested and remove 'solves', 'universal' and 'future work is unnecessary'. Evaluate at 8k–128k and compare against established long-context and gated-attention methods under matched budgets. R1, R2, R3
  4. must There is a single seed (seed 0) on n=200 with no variance or significance testing (Section 3.1, Table 1).
    → Run at least 3–5 seeds per model, and report mean ± std, confidence intervals and a significance test. R1, R2, R3
  5. should The mechanism is unexplained and there are no ablations. A static per-head scalar (Eq. 1) is input-independent, yet Section 2 claims it lets the model focus on relevant context and calls this 'self-evident'.
    → Add ablations (no gate, fixed constant gate, random head pruning, per-token gating). Analyse the learned σ(g_h) values and give an argument for why a static gate should help with length. R1, R2, R3
  6. should Novelty and related work: only Vaswani et al. is cited, and the paper does not distinguish itself from prior head-gating and head-pruning work.
    → Add a related-work section covering head gating and pruning, long-context attention and positional methods, and state the contribution relative to the closest prior methods. R1, R2, R3
  7. should Reproducibility: training data, architecture details, optimizer, learning rate, batch size, compute, and LongQA-Mini construction and format are all missing.
    → Document the full training configuration and describe how LongQA-Mini was built (question types, answer format, evidence that it requires long context). Release code and data. R1, R3
