Summary of the submission

The paper argues that linear-time-invariant (LTI) structured SSMs cannot do content-based selection. It makes the SSM parameters Δ, B and C input-dependent (S6, Section 3.2). Because this breaks the convolutional mode, it computes the model with a hardware-aware scan that never materialises the (B, L, D, N) state in HBM (Section 3.3). The result is wrapped in a homogeneous block that merges H3 and the gated MLP (Mamba, Section 3.4, Figure 3). The evaluation covers:

  • synthetic tasks (Tables 1, 11);
  • Pile scaling laws from 125M to 1.3B against a Transformer++ recipe (Figure 4, Table 12);
  • zero-shot evaluation up to 2.8B against same-data, same-tokenizer Pythia and RWKV (Table 3);
  • DNA (Figure 5, Table 13), audio (Figure 7, Tables 4-5), efficiency (Figure 8, Table 15), and 350M ablations (Tables 6-10).

Assessment

All three reviewers recommend acceptance: R1 gives 7-8 across rounds, and R2 and R3 give 8 in every round. I agree. The strengths below are well supported by the submission.

1. The central mechanism is cleanly isolated.

  • Table 1: S4→S6 raises Selective Copying from 18.3→97.0 with no gate and from 56.4→99.8 in the Mamba block. This directly tests the claim that architectural gating is not selection.
  • Table 6: every LTI layer sits at 10.24-10.75 perplexity, while S6 gives 8.95 (H3) and 8.69 (Mamba).
  • Table 7: perplexity goes from 10.93 with no selective parameters to 8.71 with Δ, B and C all selective.
  • Table 10: growing N from 1→16 helps only when B and C are selective (9.73→8.71 vs 9.88→9.81). This is a direct test of the compression-capacity argument of Section 3.1.
