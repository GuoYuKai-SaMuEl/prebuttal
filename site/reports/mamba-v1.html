AC estimate: 8/10

## Summary The submission proposes **selective SSMs (S6)**: the SSM parameters ∆, B and C become functions of the input (Algorithm 2, Section 3.2). Because this breaks the convolutional form used by prior LTI SSMs, the authors add a **hardware-aware fused scan** that keeps the expanded (B,L,D,N) state in SRAM rather than HBM (Section 3.3.2). They also propose a homogeneous **Mamba block** that merges the H3 block and the gated MLP (Section 3.4, Figure 3). The evaluation covers: - synthetic tasks (Tables 1, 2/11); - Pile language modeling, with scaling laws to ~1.3B (Figure 4, Table 12) and zero-shot evaluation to 2.8B (Table 3); - DNA (Figure 5, Table 13); - audio (Figure 7, Tables 4–5); - efficiency (Figure 8, Table 15); - ablations (Tables 6–10). All three reviewers judge the paper above the bar: R1 rates it 8, R2 rates it 6 and R3 rates it 8. No reviewer identified a fatal technical flaw, and my own reading found none. ## Strengths (consensus, evidence-backed) 1. **The core idea is clearly isolated by controlled ablations.** - Table 1: moving from S4 to S6 raises selective-copying accuracy from 18.3 to 97.0 (no gate) and from 57.0 to 99.7 (H3 architecture). The Mamba architecture with S4 reaches only 56.4, so the architecture alone does not solve the task. - Table 6: every LTI variant sits between 10.24 and 10.75 perplexity, while S6 gives 8.95 (H3) and 8.69 (Mamba). - Table 10: growing the state size N from 1 to 16 helps only when B and C are selective (9.73→8.71, versus 9.88→9.81 when they are not). This directly supports the compression/state-expansion argument of Sections 3.1 and 3.3. 2. **The systems contribution is real and necessary.** Without the fused scan, the time-varying model would be impractical.
