Answer Reviewer 2 before Reviewer 2 exists.

A pre-submission stress test for ML papers. Three AI reviewers read your paper in separate contexts, on the venue's real review form; an area chair weighs them and writes what to fix first. A free check catches what gets papers desk-rejected.

How a review runs and how to read the report

Before you submit: the desk-reject pre-flight

No model, no cost, a few seconds. A PDF, a LaTeX folder or Overleaf's source .zip.

# real output on the bundled demo paper
$ prebuttal check paper.pdf --venue icml
ICML rules (8 pages, double-blind, requires Impact Statement)

[x] format     no "Impact Statement" section
                — the venue requires one
[x] leftovers  unresolved references (??) on page 2
[ok] PDF metadata has no author
[ok] no self-revealing links or citations
[ok] main text 2 of 8 pages
[ok] no hidden text

2 problems that can get the paper desk-rejected.
Anonymity
Author names in the PDF metadata, e-mails on page 1, a camera-ready or [preprint] build, an acknowledgements section, links to your own repository, “our previous work [12]”.
Format
Main text over the page limit, two-column layouts included; a missing NeurIPS checklist, ICML impact statement, CVPR LLM usage statement or ARR limitations section.
Leftovers
??, [?], TODOs, and text hidden from human readers.
In CI
Exit code 6 on a desk-reject risk; a GitHub Action runs it on every push.

The revision loop

Every run ends with a revision plan, and every paper is a project whose runs line up as revision history. Two runs can be diffed.

# abridged output of the real runs
$ prebuttal run 2312.00752v1 --project mamba-revision \
    --note "v1 — rejected at ICLR 2024"
  R1 claude/sonnet 8 · R2 codex/gpt-6-luna 6
  R3 gemini-3.8-flash FAILED (HTTP 429)

$ prebuttal retry mamba-revision#11
  R3 gemini-3.8-flash 8
  Predicted: 7.33/10 (σ 0.94)  → saved as mamba-revision#17

$ prebuttal run 2312.00752v2 \
    --note "v2 — revised, accepted at COLM 2024"
$ prebuttal retry mamba-revision#12   # same quota, same fix
  Predicted: 7.33/10 (σ 0.94)  → saved as mamba-revision#18

$ prebuttal diff --llm mamba-revision#17 mamba-revision#18
  panel          7.33/10 → 7.33/10 (Δ +0)
  still raised:  [must] Headline claims exceed the tested regime …
  still raised:  [should] No seeds, standard deviations …
  new in B:      the custom fused CUDA kernel's portability
  0 of 8 plan items were not re-detected in B.
A plan, not just a verdict
The area chair merges the reviews into must / should / could items: the issue with its table or section, the fix, who raised it. prebuttal show --plan prints it.
Diff the next round
prebuttal diff lists what is no longer raised, what still is and what is new; --llm matches by meaning.
History per paper
The same PDF, LaTeX folder or arXiv id always lands in the same project. Runs are numbered (mamba#3) and carry your --note; prebuttal projects --open shows the trends offline.

Bring your own backend

Detected at startup; every report records which model wrote what.

Privacy. Your paper's text goes to the backend's provider, and what happens there is that provider's policy. Prebuttal runs no servers and is not a data custodian. For unpublished work, use ollama or relay, or check the provider's terms.
